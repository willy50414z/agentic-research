## 輸出

用工具將以下檔案寫入 `{OUTPUT_DIR}`：

- 必寫：`{OUTPUT_DIR}/reviewed_spec_final.md`（最終完整 spec，整合所有修正）
- 有待釐清問題時，另外寫入：`{OUTPUT_DIR}/questions.txt`（每行一個待釐清問題）
- 僅在判定 PASS 時額外寫入：`{OUTPUT_DIR}/spec_fields.json`

  `spec_fields.json` 必須是嚴格 JSON（不可有 markdown fences 或任何多餘文字），schema 如下：
  ```
  {
    "plugin":     "<外掛名稱，固定為 quant_alpha>",
    "hypothesis": "<市場論點摘要，1-3 句，取自 ## 市場論點 或 ## 對需求的理解>",
    "trading_scope": {
      "pair":      "<SYMBOL/QUOTE，例如 BTC/USDT>",
      "exchange":  "<交易所名稱，例如 binance>",
      "timeframe": "<週期，例如 1d>"
    },
    "data": {
      "train_period": {"start": "YYYY-MM-DD", "end": "YYYY-MM-DD"},
      "test_period":  {"start": "YYYY-MM-DD", "end": "YYYY-MM-DD"}
    },
    "execution": {
      "fee": "<手續費百分比字串，例如 0.10%>"
    },
    "performance": {
      "win_rate":          <IS 門檻 float>,
      "max_drawdown":      <IS 門檻 float>,
      "alpha_ratio":       <IS 門檻 float>,
      "is_profit_factor":  <IS profit factor float>,
      "oos_profit_factor": <OOS profit factor float>
    }
  }
  ```
  所有欄位必須填入具體值，不可為空字串或 null。

## 補充校正要求

5. **你是最終守門員，不是自由改寫器**
   你的首要任務是驗證 Author / Refine 輪輸出是否真的符合規則與 SOP。
   只有在以下情況才應修改內容：
   - 補齊仍缺漏的必填欄位
   - 修正內部矛盾
   - 將模糊敘述改成可執行的明確值
   不要為了風格或措辭偏好進行不必要改寫。

6. **維持後續機器可讀性**
   所有數值、區間、閾值、日期與條件都應盡量標準化表達，避免讓後續流程難以解析。
   例如：明確寫出 timeframe、交易方向、訓練/驗證/測試期間、IS/OOS 門檻與 fee/slippage 假設。
