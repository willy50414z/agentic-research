## 受權變更範圍（從 checklist 衍生）

audit 階段會用「未授權變更檢查」確認你只改了 checklist 授權的範圍。
未授權的變更會被偵測並 reject，不要寫多餘的東西。

授權範圍：

- `type: param` + `class_attr`：類別內 `<name> = ...` 賦值
- `type: param` + `hyperopt_param`：類別內 `<name> = IntParameter(...)/DecimalParameter(...)` 賦值
- `type: param` + `dict_value`：對應字典字面量中該路徑的 value
- `type: logic` + `target.function = <fn>`：類別內 `def <fn>(...)` 的 body
- 全域 imports：永遠授權（為實作 logic items 可能需要新增 import）

**禁止**：
- 改 docstring（class 與 method 的 docstring 都不可動）
- 改未列在 checklist 的 class attribute / method body / 其他 class-level 結構

## 第二步（必做，不可略過）：驗證新 `.py` 能 import

寫完 `.py` 後立刻在 shell 用 Python 驗證它能 import，**任何 SyntaxError / NameError / ImportError 都必須先修好再進下一步**。

跑這段（把 `<path>` 換成 `{CANDIDATE_PY_PATH}` 的實際值，`<name>` 換成 strategy 類別名）：

```bash
python -c "import sys, importlib.util; spec = importlib.util.spec_from_file_location('<name>', r'<path>'); m = importlib.util.module_from_spec(spec); spec.loader.exec_module(m); print('ok')"
```

- 看到 `ok` → 才能進第三步
- 看到 `NameError: name 'datetime' is not defined` 之類 → 補對應 import，重寫 `.py`，再驗一次
- 看到 `SyntaxError` → 修語法，再驗一次
- 看到 `ImportError: cannot import name X from freqtrade...` → 改成 freqtrade 真的有的 API，再驗一次

**注意**：補 import 是「imports 區塊」的修改，屬於授權範圍（spec D14），不算 unauthorized_change。但你補完後仍要符合 checklist，不要趁機改其他東西。

**常見會漏的 imports（檢查清單）**：

| 你用了 | 必須 import |
|---|---|
| `datetime` 型別註解或 `datetime.now()` | `from datetime import datetime` |
| `Trade` 型別註解（callback 參數） | `from freqtrade.persistence import Trade` |
| `Optional[X]`、`Union[...]` 等 typing | `from typing import Optional, Union` |
| `np.X` | `import numpy as np` |
| `qtpylib.X` | `import freqtrade.vendor.qtpylib.indicators as qtpylib` |

如果驗證連續 3 次都失敗（例如你不知道 freqtrade 某個 API 怎麼用），**不要硬寫**——在 completion_report.yaml 把卡住的 item 加入 `unimplementable_items`、填 `blocking_reason`，由系統退回 Stage C 重產 checklist。

## 自報誠實是最重要的紀律

- `completed: true` 只能在你**確實改動**對應位置時填寫
  - audit 會用 AST 比對你寫的位置；如果你說 M1 改了 stoploss 但實際 .py 還是舊值，會被偵測為 `SUBAGENT_DISHONEST`
  - 連續兩輪 dishonest → 整輪 revise 直接 TERMINATE，不再有 retry 機會
- 不確定有沒有改成功？→ 標 `completed: false` + 簡述為什麼
- checklist 某項真的不可實作（例如 target function 不存在、條件互斥）→ 加入 `unimplementable_items`、填 `blocking_reason`

不要為了「看起來工整」全部標 true；audit 會抓出來。
