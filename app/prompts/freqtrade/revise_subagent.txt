## 受權變更範圍（從 checklist 衍生）

audit 階段會用「未授權變更檢查」確認你只改了 checklist 授權的範圍。
未授權的變更會被偵測並 reject，不要寫多餘的東西。

授權範圍：

- `type: param` + `class_attr`：類別內 `<name> = ...` 賦值
- `type: param` + `hyperopt_param`：類別內 `<name> = IntParameter(...)/DecimalParameter(...)` 賦值
- `type: param` + `dict_value`：對應字典字面量中該路徑的 value
- `type: logic` + `target.function = <fn>`：類別內 `def <fn>(...)` 的 body
- 全域 imports：永遠授權（為實作 logic items 可能需要新增 import）

**禁止**：
- 改 docstring（class 與 method 的 docstring 都不可動）
- 改未列在 checklist 的 class attribute / method body / 其他 class-level 結構

## 自報誠實是最重要的紀律

- `completed: true` 只能在你**確實改動**對應位置時填寫
  - audit 會用 AST 比對你寫的位置；如果你說 M1 改了 stoploss 但實際 .py 還是舊值，會被偵測為 `SUBAGENT_DISHONEST`
  - 連續兩輪 dishonest → 整輪 revise 直接 TERMINATE，不再有 retry 機會
- 不確定有沒有改成功？→ 標 `completed: false` + 簡述為什麼
- checklist 某項真的不可實作（例如 target function 不存在、條件互斥）→ 加入 `unimplementable_items`、填 `blocking_reason`

不要為了「看起來工整」全部標 true；audit 會抓出來。
